1. Ringkasan Kasus & Arsitektur Sistem

SIAKAD Mini adalah layanan akademik berbasis RESTful API yang mengelola data mahasiswa, mata kuliah, dan Kartu Rencana Studi (KRS) secara terpadu, aman, dan berkinerja tinggi.

  • Bahasa Pemrograman: Go (Golang) 1.26.5
  • Framework Web: Fiber v2
  • Basis Data: PostgreSQL dengan connection pool (pgx v5)
  • Autentikasi: JSON Web Token (JWT) Bearer Token
  • Keamanan: Hash Bcrypt untuk seluruh password akun
  • Rate Limiting: Maksimal 5x kegagalan login per menit (HTTP 429)
  • Concurrency: Database transaction & Row Locking (SELECT ... FOR UPDATE) pada penambahan KRS

2. Skema Basis Data Relasional

Tabel Kolom Utama Relasi & Constraints
users id (PK), email (UK), password, role, is_active 1-to-1 dengan students
students id (PK), user_id (FK), nim (UK), nama, prodi, angkatan, ipk_terakhir, deleted_at 1-to-Many dengan enrollments
courses id (PK), kode_mk (UK), nama_mk, sks, semester, kuota 1-to-Many dengan enrollments
enrollments id (PK), student_id (FK), course_id (FK), tahun_akademik, created_at UNIQUE (student_id, course_id, tahun_akademik)

3. Implementasi Business Rules

  1. Batas SKS berdasarkan IPK Terakhir:
    • IPK ≥ 3.00 → Maksimal 24 SKS
    • 2.50 ≤ IPK < 3.00 → Maksimal 21 SKS
    • IPK < 2.50 → Maksimal 18 SKS
  2. Pencegahan Duplikasi KRS: Mahasiswa tidak dapat mengambil mata kuliah yang sama dua kali pada tahun akademik yang sama (HTTP 409 Conflict).
  3. Concurrency & Row Locking: Pengambilan KRS mengunci baris mata kuliah dengan SELECT ... FOR UPDATE dalam DB transaction untuk mencegah kuota terlampaui.
  4. Ownership Hak Akses: Mahasiswa hanya dapat melihat data profilnya dan membatalkan KRS miliknya sendiri (HTTP 403 Forbidden jika mengakses milik orang lain).
  5. Soft Delete Mahasiswa: Mengisi timestamp deleted_at. Mahasiswa yang dihapus tidak muncul di daftar dan tidak dapat login (HTTP 401 Unauthorized).

4. Implementasi 10 Endpoint RESTful API

POST /api/v1/auth/login (Publik, Status: 200 OK)

Login pengguna, verifikasi kredensial, dan mengembalikan JWT Access Token.

GET /api/v1/auth/me (Semua Role, Status: 200 OK)

Mengembalikan profil user yang sedang login beserta detail student jika role mahasiswa.

GET /api/v1/students (Admin, Status: 200 OK)

Daftar seluruh mahasiswa aktif dengan pagination (page, per_page), filter (prodi, angkatan), search, dan sort.

POST /api/v1/students (Admin, Status: 201 Created)

Menambahkan data mahasiswa baru dan membuat akun user otomatis (password awal = hash NIM) dalam 1 transaksi.

GET /api/v1/students/{id} (Admin & Mahasiswa Sendiri, Status: 200 OK)

Menampilkan detail mahasiswa, daftar mata kuliah yang diambil, total_sks, dan batas_sks.

PUT /api/v1/students/{id} (Admin, Status: 200 OK)

Memperbarui data mahasiswa (nama, prodi, angkatan, ipk_terakhir). NIM tidak dapat diubah.

DELETE /api/v1/students/{id} (Admin, Status: 204 No Content)

Melakukan soft delete pada data mahasiswa.

GET /api/v1/courses (Semua Role, Status: 200 OK)

Daftar seluruh mata kuliah dengan perhitungan kolom terisi dan sisa_kuota.

POST /api/v1/enrollments (Mahasiswa, Status: 201 Created)

Mengambil mata kuliah (KRS) dengan validasi kuota (row lock) dan batas maksimal SKS.

DELETE /api/v1/enrollments/{id} (Mahasiswa Milik Sendiri, Status: 204 No Content)

Membatalkan mata kuliah dari KRS mahasiswa yang sedang login, mengembalikan kuota kelas.
